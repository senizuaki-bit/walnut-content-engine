# 核桃世界接入配置总指南

Windows 一键联动包有四种使用层级。它们彼此独立，第一次体验不需要一次性配置所有服务。

| 使用目标 | 是否必须联网 | 需要的账号或密钥 | 入口 |
|---|---:|---|---|
| 运行数据花园游戏与已发布内容 | 否 | 无 | `运行数据花园Demo.bat` |
| 启用小核桃个性化提示 | 是 | DeepSeek API Key | `配置DeepSeek密钥.bat` |
| 从飞书修改、审核并发布内容 | 是 | 飞书账号、Base 编辑权限、lark-cli | `配置飞书多维表格.bat` |
| 用 AI 世界工坊生成文案与皮肤 | 是 | 火山方舟 API Key；DeepSeek 可作后备 | `配置火山引擎.bat` |

## 先跑通离线 Demo

1. 完整解压 ZIP；不要直接在压缩软件预览窗口里运行。
2. 双击 `运行数据花园Demo.bat`。
3. 启动器会校验并编译包内内容，启动本地 AI 安全代理，再打开 Godot 游戏。
4. 关闭游戏后，启动器只清理由它本次创建的后台进程。

一键包已经携带 Godot 和 Node.js。未配置 DeepSeek 时，小核桃使用内置五级提示；未登录飞书时，游戏读取包内已经发布的内容。因此，评审和试玩不会被外部服务阻塞。

## 在线接入顺序

建议按实际需要配置：

1. 先配置 DeepSeek，验证小核桃 AI。
2. 需要演示“飞书改内容 → 自动校验/编译 → 游戏读取”时，再配置飞书。
3. 需要生成新世界皮肤时，最后配置火山引擎；真实文生图会产生费用。

详细步骤：

- [DeepSeek 接入教程](DeepSeek接入教程.md)
- [飞书多维表格接入教程](飞书多维表格接入教程.md)

## 密钥、权限与费用

- API Key 只保存在本机 `xiao-hetao-ai-server/.env`，不会写进 Godot 资源或内容包。
- `.env`、飞书 OAuth 凭据、日志和运行缓存均不应上传或转发。
- 飞书脚本以登录用户身份访问 Base；发布需要目标 Base 的编辑权限。
- `验证DeepSeek连接.bat` 和 `验证火山引擎连接.bat` 会在确认后发起一次很小的真实请求，可能产生少量费用。
- 世界工坊默认断点续跑。只有显式使用 `--fresh` 才会重新生成全部付费素材。

## 故障定位

- 游戏打不开：确认已经完整解压，并检查路径中是否被杀毒软件隔离了 `tools` 下的可执行文件。
- DeepSeek 验证失败：检查 Key、余额、模型权限和网络代理。
- 找不到 `lark-cli`：安装后关闭并重新打开 PowerShell，再执行 `lark-cli --version`。
- 飞书返回无权限：当前飞书账号需要被添加为目标 Base 的可编辑成员。
- 火山引擎返回 401/403/404：依次检查 API Key、模型是否已开通、模型 ID 是否与控制台一致。

## 联动链路

`飞书内容控制面 → 内容校验与编译 → 带版本/哈希的 Godot 内容包 → 游戏运行 → 学习事件聚合 → 飞书课堂证据`

DeepSeek 只改写分级提示的表达；火山引擎只生成受限世界文案和皮肤素材。程序语义、诊断规则、通过条件、提示等级和安全边界仍由本地确定性代码控制。

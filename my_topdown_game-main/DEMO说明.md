# 核桃代码世界 · 多场景 P0 Demo

> 产品与流程以内部 v2.1 产品基线为最高优先级：它定义 P0 范围、信息架构、主循环、教学合同、AI 边界和验收标准。公开仓库不分发该内部原文。《世界观》（v1.4）只覆盖地点、角色、冲突、奖励称谓和语气，不得反向改写产品合同。当前映射见 [design/source-gameplay-worldbuilding-map.md](design/source-gameplay-worldbuilding-map.md)。

当前主线已经从单场景“数据花园”切换为可行走家园、主题地图、关卡准备、独立房间链、Boss、结算和四个独立家园设施。旧版单场景仍保留为回归入口，不再代表主流程。

## 一键启动

双击项目上一级目录的 [运行核桃代码世界Demo.bat](../运行核桃代码世界Demo.bat)。兼容入口 [运行数据花园Demo.bat](../运行数据花园Demo.bat) 调用同一个启动器。

启动器会：

1. 优先使用本机 `tools/` 下的 Godot 4.5.2 便携运行时；未附带时回退到系统 `PATH` 中的 Godot；
2. 在本机需要时启动小核桃代理；
3. 有可用且已验证的内容包时加载该版本，发布失败则保留上一个已验证版本；
4. 退出游戏后只关闭本次启动器创建的后台进程。

主场景为 [scenes/demo/loop_oasis/home_base.tscn](scenes/demo/loop_oasis/home_base.tscn)。无需安装 Godot，也不需要联网才能走通确定性主线。

## 操作

### 通用

- 移动：WASD 或方向键；
- 世界交互、拾取、确认：走近实体后按 E 或回车；
- 瞄准与射击：移动鼠标，按鼠标左键；
- 返回上一个空间/芽芽家园：Esc；
- 家园路线提示：M；
- 家园设施失败后无损重试：R；
- 鼠标始终使用系统光标，不会被 Demo 隐藏。

### 编程与战斗

- 观察房：走近装置按 E，执行一次真实世界动作；
- 安全编程房、谜桥和迁移房：走近控制台按 E，用 + / - 调整 Repeat，再运行或重置；
- 脉冲防线：移动、鼠标射击；Q 使用一次循环脉冲；
- Boss：先在场内移动观察节拍，再进入安全 Debug，最后继续用真实射击完成净化；
- 房间合同通过后出现实体宝箱；开箱后出现星光门，必须亲自走入才能离开。

### 四个家园设施

| 地点 | 操作与成功条件 | 可见失败 |
|---|---|---|
| 芽芽家园·编程农场 / 叮当 | 走到四块地旁按 E 播下清泉种子；在叮当控制台用方向键调 Repeat，按 E 启动无人机；观察四次实体浇灌后逐块按 E 收获 | Repeat 不是 4、缺少清泉种子；显示机器码，资源不被不可逆消费 |
| 小核桃成长舱 | 按 1→5 走访本局证据节点并按 E 接入；在成长舱放入农场作物；与小核桃走过三束校准光 | 顺序错误、缺少冒险/农场证据；保留已有长期进度 |
| 书书知识星图 | 按 1→3 读取编程、战斗、农场知识站，再沿亮线走到对应回声端点 | 顺序错误或来源证据缺失 |
| 叮当师傅工坊 | 走到校准台按 E 领取工具；用真实子弹击中三座完全静止、不会攻击和接触伤害的安全靶 | 六发校准能量结束后仍未完成；无伤害、无倒计时、可按 R 重试 |

## 完整 P0 流程

| 顺序 | 场景 | 独立可玩内容 | 进入下一步所需世界证据 |
|---|---|---|---|
| 1 | 芽芽家园 | 自由行走，观察世界门、伙伴和四个设施 | 亲自靠近世界入口 |
| 2 | 星光群岛主题地图 | 走到“先解谜”或“先战斗”的实体星光门 | 选定路线；两条路线仍同时包含解谜和战斗 |
| 3 | 阿探队长整备房 | 走到工具台拾取真实武器，并用真实 Bullet 命中实体训练靶 | 工具已装备、训练靶真实命中 |
| 4 | R0 干涸花园 | 触发一次动作，观察只改变 1/5 目标 | 移动、动作运行和目标变化 |
| 5 | R1 安全阀门阵 | 运行 Repeat(5)，观看五步轨迹逐个改变世界 | 五个目标与五步执行轨迹 |
| 6—7 | 谜题小桥 / 脉冲防线 | 路线只交换先后；谜桥完成 5→4 反事实并亲自过桥，防线必须移动、脉冲、射击并清敌 | puzzle_clear 与 combat_clear 双必经 |
| 8 | R4 新任务巡查 | 在陌生布局中用同一结构处理六个目标 | 六步无提示迁移轨迹 |
| 9 | 迷糊小伙伴 Boss | 观察四拍 → 运行缺陷程序 → 修正安全条件 → 实战净化 6 HP | boss_observe、boss_debug、boss_combat 三段证据 |
| 10 | 结算 | 汇总房间证据，领取清泉种子和法则碎片 | 八个必经房间标记齐全，奖励只提交一次 |
| 11 | 编程农场 | 四地块播种、Repeat(4) 无人机浇灌、收获 | 作物完整生命周期 |
| 12 | 成长舱 | 冒险证据 + 农场作物 + 三点校准 | 小核桃突破、作物消费 |
| 13 | 知识星图 | 顺序回放编程、战斗、农场三段轨迹 | 有序个人轨迹 |
| 14 | 工坊 | 拾取工具并真实击碎三座静止靶 | 真实 Bullet 命中与靶体销毁 |

所有顶层地点都是独立 .tscn。大按钮、弹窗和测试快捷键不能直接写入完成状态；只有世界行为收集到证据并通过合同后，才会保存进度、发放奖励或解锁出口。

## 自动化边界

自动化分成两层，二者不能互相冒充：

1. **每场景物理/实体测试**：验证移动或近身交互、真实武器与 Bullet、Enemy 受击/死亡、房门、宝箱、传送门、设施实体生命周期；入口包括 --home-test、--theme-map-test、--level-prep-test、--adventure-room-test、--facility-test、--settlement-test 和 [qa/source_room_stage_test.tscn](qa/source_room_stage_test.tscn)。
2. **全链合同/状态测试**：[qa/multiscene_e2e_harness.tscn](qa/multiscene_e2e_harness.tscn) 在单进程内覆盖两条路线、门禁、八个房间、Boss 三阶段、四个家园活动、奖励幂等、保存加载、篡改拒绝和“弹窗不能伪完成”。

当前全量脚本从头通过，汇总标志为 ALL_AUTOMATED_TESTS_OK cases=24；随后对本地 `qa/logs/final/` 的诊断扫描通过 FINAL_LOG_DIAGNOSTIC_SCAN_OK。成长舱修复退出竞态后连续 10 次压力复跑零告警，正常 GUI 主场景启动 exit 0 且无诊断。

主要分项标志包括：

- HOME_BASE_SMOKE_OK、THEME_MAP_SMOKE_OK、LEVEL_PREP_SMOKE_OK、SETTLEMENT_SMOKE_OK；
- FACILITY_SCENE_OK farm、growth、archive、workshop；
- MULTISCENE_SCENE_CONTRACT_OK、MULTISCENE_ROUTE_PUZZLE_FIRST_OK、MULTISCENE_ROUTE_COMBAT_FIRST_OK、MULTISCENE_GATES_OK、MULTISCENE_PERSISTENCE_OK、MULTISCENE_NO_POPUP_FAKE_OK、MULTISCENE_E2E_OK。

全链 harness 是合同与状态编排，不是一个机器人连续操作全部 14 个场景；“每场景物理测试 + 全链合同/状态测试”共同构成当前证据。

旧版 [data_garden.tscn](scenes/demo/data_garden/data_garden.tscn) 仅用于 --demo-test、--demo-ai-test 和 --demo-capture-flow 回归，不属于当前多场景主线。

## 小核桃 AI：当前验收范围

- 关卡判定、执行轨迹、错误类型、奖励和成长都由 Godot 确定性系统决定；
- 小核桃只消费白名单结构化状态并生成/选择提示，不具备改程序、改分数、发奖励或发布内容的权限；
- **本次多场景收口和自动化验收只使用本地 mock/固定提示，未向 DeepSeek 发送任何数据，也未把 XIAO_HETAO_DEEPSEEK_LIVE_OK 计入验收证据**；
- 本地代理合同和 Godot→代理接口可以单独测试，但不等于真实模型连通；
- 如后续明确配置真实 Key，必须按 [DeepSeek 接入教程](../docs/DeepSeek接入教程.md) 单独执行、记录和披露，不能把 mock 标志写成 DeepSeek 实跑。

视觉与交互现状、官方参考及尚未封板的问题见 [design-qa.md](design-qa.md)；P0 要求逐项映射见 [design/prototype-v2.1-compliance.md](design/prototype-v2.1-compliance.md)。

## 操作

### 芽心基地

- 移动：`WASD` 或方向键
- 打开/关闭冒险路线图：`M`
- 靠近世界门或设施交互：`E` 或回车
- 关闭路线图：`M` 或 `Esc`

### 循环绿洲

- 移动：`WASD` 或方向键
- 观察、确认和环境交互：`E` 或回车
- 预测：在中央控制台选择一种结果
- 编排：把“生长/巡检”拖进橙色重复结构；单击动作也提供无障碍替代操作
- 调整次数：点击橙色结构，或使用界面上的次数控制
- 运行：点击运行按钮，或按回车
- 请求提示：`H` 或点击小核桃出现时的“提示 H”
- 战斗射击：鼠标左键朝光标射击；`Space` 自动瞄准射击
- 可选探索：迁移阶段靠近左侧记忆晶体，按 `E`
- 完成后重玩：`R`

鼠标始终使用系统光标，不会因进入 Demo 而隐藏。

## 完整纵向切片

1. **可行走家园**：玩家在芽心基地认识世界门、四格编程农田、成长舱、知识档案馆和小核桃；按 `M` 查看路线，靠近世界门按 `E` 出发。
2. **感知规律**：5 颗光种保持休眠，小核桃不预先说“循环”。
3. **预测结果**：玩家预测只执行一次 `生长` 会发生什么，再让世界验证；一次只亮一颗。
4. **编排与追踪**：自然语言目标先出现，随后把“生长”拖进“重复”结构；程序逐行高亮，连接线、当前光种和代码轨迹同步发光。
5. **反事实验证**：先让 5 颗光种全部生长，再必须把次数从 `5` 改成 `4`；最后一颗会明确保持休眠。
6. **常规战斗**：反事实实验结束后进入三只错误怪的战斗房。玩家必须移动和射击并清空敌人，不能跳过后直接进入迁移。
7. **陌生迁移**：不提示结构名称，独立控制巡检器检查 6 个新目标。
8. **抽象命名**：小核桃最后才说明“这个结构叫循环”，并显示第四层 C 语言代码：

```c
for (int i = 0; i < 5; i++) {
    grow();
}
```

9. **Boss Debug**：先观察“护盾 → 弱点 → 护盾 → 弱点”四拍，运行会错误攻击护盾的缺陷程序，再把条件修为“仅在弱点暴露时攻击”。
10. **Boss 实战**：Debug 成功只会解除程序锁。随后还要在场景中移动并用鼠标左键或 `Space` 射击，真正击败守门者。
11. **结算回家**：结果页可以重玩、留在绿洲，或“带着水脉种子返回芽心基地”。回家后能看到水脉种子已入库、编程农田出现 `Repeat(4) → water_next_plot()`、小核桃成长至 Lv2，并在知识档案馆留下学习记录。这里是一次新的迁移：结构保持 Repeat，次数由冒险的 5 个光种调整为家园的 4 格土地。

代码按四层逐步显形：**世界行为 → 自然语言指令 → 积木/流程结构 → C 语言代码**。

## 小核桃 AI

小核桃只承担四项职责：新手引导、分级提示、学习反思、长期陪伴与成长记录。它不是泛化聊天机器人。

- 游戏本地状态机负责全部判题、执行轨迹和过关结果；DeepSeek 不能决定正确与否，也不能替玩家修改程序。
- AI 只读取年龄段、当前阶段、当前程序、最近一次修改、确定性错误类型、尝试次数和提示等级等结构化状态。
- 提示阶梯依次为：确认目标 → 观察世界偏差 → 指出代码区域 → 给部分结构/轨迹 → 展示完整答案并标记复练。
- 第五级只展示答案，不会自动替玩家把次数改成 `5`；结算会记录“需要复练”。
- 无 Key、断网、超时、余额不足或限流时，会自动使用同一规则的本地提示。

配置方法见 [DeepSeek 接入教程](../docs/DeepSeek接入教程.md)。

## 两段战斗的通关边界

- 常规战斗是主线硬门槛：3 只错误怪全部清除后，才会开放 6 目标迁移。
- Boss Debug 不是最终结算：修正条件并通过四拍轨迹后，必须继续完成移动/射击 Boss 实战。
- 小核桃助力只回放执行轨迹，不排除答案或代替修改。

## 一节课建议节奏

- 0–5 分钟：探索芽心基地，使用 `M` 路线图和 `E` 世界门。
- 5–13 分钟：观察 5 颗光种，完成单次生长预测。
- 13–23 分钟：拖入动作、调整次数、逐行观察世界执行。
- 23–29 分钟：完成 `5→4` 反事实实验并讨论证据。
- 29–34 分钟：完成必须经过的常规战斗。
- 34–39 分钟：完成 6 目标陌生迁移、概念命名和 C 代码显形。
- 39–44 分钟：完成 Boss Debug 与移动/射击实战。
- 44–45 分钟：阅读学习证据并返回芽心基地观察成长变化。

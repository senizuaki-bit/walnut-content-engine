# 核桃代码世界 Demo：玩法参考与世界观落地表

> 决策优先级：《核桃代码世界_AI原生全量原型方案_v2.1.md》是产品与系统基座，决定 P0 范围、信息架构、主循环、教学合同、AI 边界和验收；《核桃代码世界·世界观 v1.4》只把角色、地点、冲突、奖励称谓与语气映射到这套基座；用户提供的 Godot 4《元气骑士》类源码只提供房间制动作玩法骨架与现有像素资源。叙事映射和参考玩法都不得反向改写 v2.1。

## 两条不可混淆的基线

- **产品基线（最高优先级）**：家园整备 → 主题地图 → 关卡准备 → 5 个房间 + Boss → 结算 → 农场自动化 → 小核桃突破；解谜与战斗双必经，失败可恢复，受限 C++/IR 与确定性证据拥有最终判定权。
- **动作玩法基线**：可行走大厅 → 实体入口 → 房间封锁 → 世界内战斗/互动 → 实体宝箱 → 星光传送门 → 通关结算。
- **叙事映射基线**：星光群岛、魔法石、bug 军团、迷糊小伙伴、芽芽家园与七块知识碎片。不得照搬第三方角色、美术或叙事，也不得改变产品合同与经济护栏。

## 角色与敌人语义

- 普通敌人是 **bug 军团**：可爱、灰绿色、造成异常但不恐怖。
- Boss 是被污染的 **迷糊小伙伴**，不是坏人；结尾表现为抖掉 bug 迷雾、恢复清醒。
- 失败文案只描述“缠结更深，可以立即重试”，不羞辱儿童、不扣除长期资源。
- 首张切片奖励固定为：循环魔法碎片、清泉种子、勇气种子、核桃币与洞察经验。

## 验收红线

1. 大按钮、弹窗或测试快捷键不能直接写入通关状态。
2. 每个冒险地点必须是独立 `.tscn`，且具备移动、实体边界、门禁和成功/失败状态。
3. 编程面板只能操作世界装置，不能代替房间玩法。
4. 所有进度写入先过 `LoopSceneContract`；拒绝结果必须带机器可读错误码并显式显示。
5. 截图验收必须把官方实机参考和当前运行截图并排比较，不能只看单张成品图。
